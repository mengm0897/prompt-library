# Prompt 库 · MVP 功能与结构

> 2026年10月13日按首次迭代后的当前代码更新。本文回答“这个本机工具能做什么、数据在哪里”；操作步骤见根目录 README，开发记录见本机项目 STATUS。

## 一句话目标

让一个人把常用提示词保存在自己的电脑上，之后能找到、阅读、修改和备份。最小闭环是：**启动 → 新增一条 → 找到它 → 关闭并重启后仍能读回**。

## 使用流程

```text
新用户首次启动
  → 看到 2 条虚构示例
  → 新增或修改提示词
  → 搜索／筛选／阅读／复制
  → 关闭服务并重启
  → 从本机文件找回内容
```

它是本机工具：浏览器连接本机 Python 服务，不需要账号、云端存储或模型 API。网页关闭后，已保存的内容仍在本机文件里。

## 当前功能

| 用户动作 | 当前行为 | 数据位置或边界 |
|---|---|---|
| 首次启动 | 没有 SQLite 数据库且 `prompts/` 没有 Markdown 时，复制两条虚构示例；生成默认分类和索引 | `examples/` 是公开样本；`prompts/`、`data/` 是每位用户自己的资料 |
| 浏览与查找 | 按关键词、一级分类、子类和状态筛选；打开详情可看排版正文或 Markdown 原文并复制 | 网页从 `/api/prompts` 取得条目，在浏览器内筛选 |
| 新增 | 粘贴正文，或选取 `.md`／`.txt` 载入正文后保存；填写标题、分类和状态 | 本机服务创建 `prompts/编号.md`，同时更新 SQLite |
| 编辑与归档 | 修改标题、正文和元数据；可归档、恢复 | 更新同一条 Markdown 和 SQLite；归档不删除文件 |
| 删除提示词 | 在详情页确认后永久删除单条提示词 | 删除对应 Markdown 和 SQLite 记录；附件保留，只能从已有备份恢复 |
| 管理分类 | 在网页新增、重命名、删除大类和子类；删除被使用的分类需先选择迁移目标 | 修改 `data/taxonomy.json`、涉及的 Markdown 和 SQLite 索引 |
| 使用附件 | 正文引用 `图片和附件/文件名` 时，详情页可显示图片或链接 PDF | 用户自己把文件放进本机目录；网页没有上传附件功能 |
| 备份与导入 | 导出含正文的 JSON；导入时跳过已存在的重复条目 | 导出的 JSON 是私人数据，应由用户自行保管 |

## 文件和数据怎样配合

```text
app/web/ 页面
    ↓ HTTP 请求
app/server.py 本机服务
    ├─ app/md_store.py → prompts/*.md：正式提示词
    ├─ data/taxonomy.json：分类词表
    ├─ data/prompts.sqlite3：网页检索索引，也含正文
    └─ 图片和附件/：用户自行加入的本机文件
```

新增时，页面把内容 POST 到本机服务；服务校验后写入 Markdown，并更新 SQLite。读取时，服务先同步 Markdown 的变化，再从 SQLite 返回条目。默认分类写在 `app/md_store.py`；已有用户的实际分类由自己的 `data/taxonomy.json` 决定。

旧版本的 `tags`、`source`、`note` 字段不再属于当前数据结构。升级读取旧 Markdown 时，服务会移除这些元数据并重建 SQLite 索引；提示词正文保持不变。升级前建议自行备份 `prompts/` 和 `data/`。旧版 JSON 备份仍可导入，旧字段会被忽略。

## 本版暂不支持

- 将多个分类批量合并成一个新分类；目前可逐个选择迁移目标并删除。
- 在网页上传附件；目前由用户自行放入本机目录。
- 登录、云端同步、多人共享或 AI 自动生成提示词。

这些是后续可选迭代题目，不影响本机保存与找回的最小闭环。

## 验收范围

- 已在干净副本验证：首次看到两条示例、新增一条、重启后读回；隔离副本中还验证了编辑、归档与恢复、分类新增、附件读取和 JSON 导入导出。
- 尚待真人按 README 试用：浏览器中的搜索与筛选、阅读和编辑体验，以及没有项目背景的人能否独立完成最小闭环。
- 公开边界：仓库只放工具代码、本文、README、测试和两条虚构示例；每位用户的 `prompts/`、`data/`、附件和备份不进入公开提交。

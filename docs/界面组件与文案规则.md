# Prompt 库界面组件与文案规则

> 2026年10月14日。经可交互原型确认的视觉决策，以 [视觉基准](视觉基准.md) 为主来源。本文保留组件与文案的执行约定；实现入口是 `app/web/style.css` 的变量与通用组件，分类页补充规则在 `app/web/taxonomy.css`。

## 层级与排版

| 层级 | 用处 | 当前规则 |
|---|---|---|
| 页面标题 | 说明当前工具 | 26–34px；只出现一次 |
| 区域标题 | 分类结果、分类页“大类／子类” | 18px；同层级同字重 |
| 卡片标题 | 提示词名称 | 18px；允许换行，不截断标题 |
| 正文与按钮 | 摘要、表单和操作 | 14px；按钮最小高度 42px |
| 辅助信息 | 分类、数量、状态 | 12–13px；颜色退后，但保持可读 |

页面和弹窗都左对齐。间距使用 `--space-1` 至 `--space-10` 的 4px 倍数；边框、圆角、颜色和字号在 `:root` 统一定义，不为每个字段单独定一套值。键盘聚焦状态、窄屏布局和减少动画偏好也属于组件规则。

## 组件职责

- **顶部操作**：“管理分类”与“新增提示词”并列使用同一淡紫填充按钮。备份属于资料管理，留在侧栏。
- **提示词卡片**：桌面两列、窄屏一列。卡片内依次显示标题、最多两行摘要、底部分类；只有历史参考或归档时才补充状态。卡片共用边框、内边距、圆角、悬停与键盘聚焦样式，长标题允许换行。
- **分类管理**：左栏管理大类，右栏管理子类；“大类／子类”标题与“新增大类／新增子类”按钮顶端对齐。大类操作在左栏对应行，子类操作在右栏对应容器；图标带文字提示和无障碍名称。删除使用危险色的最终提交按钮，使用中分类必须先选迁移目标。
- **表单**：字段名称和输入框共用字号、间距与边框规则；主按钮用于完成，次按钮用于取消。文字多的提示词正文获得主要编辑面积。
- **流程**：从详情进入编辑，取消时回到同一条详情；分类弹窗打开期间暂停后台列表刷新，避免正在填写的表单被重建。删除提示词从详情进入独立确认框，先写清永久删除与备份恢复，再用危险色执行按钮；取消时回到同一条详情。窄屏只改变排列，不隐藏备份入口。

## 文案规则

控件直接写动作和对象，例如“管理分类”“新增提示词”“保存名称”。输入项已有可见标签时不再重复写解释性占位符。说明文字只在有隐藏后果时出现，例如“将迁移 2 条提示词”；成功提示只报告结果。空状态只说明当前结果，不写情绪化或营销式句子。技术词如 Markdown 保留在确实需要选择查看方式的位置，不放进无关的操作提示。

## 色彩职责

- **蓝色**用于保存等完成动作，以及搜索和正文阅读中的链接；主要按钮用深蓝文字或底色保证可读性。
- **紫色**用于当前分类和列表项的分类信息，让使用者快速辨认“这条属于哪里”。
- **黄色**用于品牌标记与“历史参考”状态；归档继续用中性灰，避免把所有状态都涂成亮色。
- 正文与长列表以白色为底，彩色集中在入口、筛选和辅助标记，不把大块高饱和背景放在阅读区。

这套规则解决一致性、阅读负担与误操作风险。改配色或字体时优先修改共享变量和组件，不逐页覆盖。参考图用于提取色彩关系，不复制其具体插图和版面资产。
